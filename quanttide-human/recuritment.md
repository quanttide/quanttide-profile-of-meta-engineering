# 改进招聘考核流程

## 需求

我们在改进招聘考核流程。流程分两种模式：课堂和招聘——课堂跟着我们的标准化任务走，招聘自由选题。

之前我们是在尝试把课堂和招聘的流程融合，在这个过程中有不少摸着石头过河的调整。

背后真正的难题不是定流程：我们的流程一直在变，今天定的下周就改。真正想找的，是我们的方式中不变的那个部分——流程怎么变，它都在的那件东西。

## 意图

先问那个靠前的问题：这件事里到底有什么东西存在。

摊开看，真实存在的是五样。候选人——被考核的主体，有边界、能被指认。任务——交给候选人的那件事，课堂给标准集，招聘自选。评价——评委对候选人在一个维度上的一次打分。结论——考核对候选人的最终判定，一人一个。流程——把任务、评价、结论串起来的步骤序列；需求已写明它今天定下周改，所以它是配置，不是本质。模式与任务来源是参数。

据此立下的形式表达：

```text
Flow   ::= steps : Sequence[Step]        # 可变——今天定下周改的那个
mode   : {课堂, 招聘}                     # 只决定任务来源
task   : 标准任务集 | 自选题

Criterion ::= dims  : List[Dim]          # 评价维度
              grade : Dim → Level        # 每维的分级描述
              pass  : List[Eval] → Bool  # 结论由评价按 grade 导出

inv1 ≡ 每个候选人恰好一个最终结论
inv2 ≡ 结论作出前，该候选人已有评价
inv3 ≡ 结论 = pass(评价)                 # 判定可重算，只认 Criterion 明写的标准
inv4 ≡ Criterion 不由 mode 决定           # 招聘与课堂同尺度（待校准）
```

不变量管「不许破」，Criterion 管「怎么算好」：一版新流程算改进，当且仅当 inv 全部成立，且每条维度仍是明写的标准，没有一条退回口头默契。哪条断言进 inv、哪条进参数，拿摸着石头过河留下的每一版流程代入裁定——每一版都成立的才是不变量，只在几版成立的是参数。

据此立下的判断：流程里不变的那件东西不是某一步骤，是标准的显式性——流程随便改，Criterion 必须明写、可重算、跨模式同尺度。
