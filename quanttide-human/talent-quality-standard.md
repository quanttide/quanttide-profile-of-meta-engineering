# 人才质量的标准

## 需求

人事体系里缺一样东西：**衡量人的标准**。早先建模时漏掉了这一层——体系被当成了流程与环节的集合，没有人问过「我们凭什么说这个人可以、那个人不行」。

念头落成一句需求：**为「人才质量」立一个基本单元，人事的各环节都挂到它上面去。**

这句话派不出去。它由好几件事攒成，而且大部分决定不在「写一条标准」里：标准用什么表述（产出与消费的关系、产出与治理成本的关系）；由谁去衡量，衡量出来的东西算不算事实；招聘、绩效、培训这三个环节各自挂上去之后，分别变成什么动作；这套标准要不要带审计属性、按什么节奏审计；考核时信息给到什么程度、要求的自主性到什么程度。每一条都会改标准写成什么样。把这些都留给「写」，上手的人只能拿模糊话把没定的地方糊过去，交一条听着对、却卡不住任何人的标准。

这篇要做的就是把这句话拆到每一件都能单独派人做、做完有办法判。拆的时候盯三件事：派给谁，怎么算完，得等谁先做完。

## 意图

先问一个更靠前的问题：这件事里到底有什么东西存在。

摊开看，真实存在的是三样。**人**——候选人、学员、员工，有边界、能被指认，是这件事唯一的对象。**标准**——衡量人才质量的那把尺子，归载体，它本身不是人也不是动作，全部意义在于被用。**招聘、绩效、培训**——三个动作，各自把人从一种状态带到另一种状态。至于「可靠不可靠」「学到什么程度」「值不值得留」，说的是人处在哪一步，归状态，本身不占一样东西。对象、动作、载体、状态各归各位。

据此立下的判断是：**这件事的单位是人这个对象，以及衡量它的那把尺子；招聘、绩效、培训只是尺子在三个环节上的动作。**尺子不立，三个环节各说各话——招聘凭印象、绩效凭感觉、培训凭课时，谁也接不上谁。

从同一条判断里牵出三处。

第一处是标准本身怎么表述。现在能说清的只有一句：**他产生知识的能力大于他消费知识的能力**——输出要高于治理他的成本。这条说的是人或值得录取、或不值得，判得出来，所以它够格当标准的内核；但它还只是内核，没到可核对的式子。

第二处是标准的性质。它要带**治理属性与审计属性**：默认假设这个人不可靠，然后持续审计他可靠不可靠。也就是说，标准不是一次性的准入判定，是一段持续的关系——这决定了它得有周期、有留痕，不能只有一张名单。

第三处是判据的取法。同一个标准落到不同环节，判据的硬度差得很远。可机械核对的（回复习惯——是只有「收到」，还是有明确的反馈；产出的件数与流转）能写成程序判；只能读懂才判得出的（在供应商处境下能否理解对方、沟通是否专业）归智能体或人；没有客观标准只能拍的（这个人是否值得长期投入）留给人。**人只出现在两类位置：需要有人担后果的，和没有客观标准、只能拍的。**

把这个拆法写成单元。一个任务单元记五项：

```text
任务单元 ::= 名字
             执行者 : {agent, human}
             前置   : 状态上的条件
             后置   : 状态上的条件
             判据   : 可判定的完成条件
```

判据的三种取法：

```text
判据执行者 : {rule, agent, human}
```

一条需求写成目标：

```text
目标 G ≡ 存在一条标准 s · s 写明了人才质量的判法（产出大于消费、输出高于治理成本）与它的审计节奏
```

分解是拿出一组任务单元 T = {t₁, …, tₙ}，再给出先后关系 ≺，满足三条：终态蕴含目标、依赖保证前置、每个 tᵢ 的判据可判定。

七个任务单元：

| 任务单元 | 执行者 | 前置 | 判据 |
|:--|:--|:--|:--|
| 定质量表述 | human | 无 | 人拍板：质量用什么表述、边界在哪，写死 |
| 定审计节奏 | human | 无 | 人拍板：默认不可靠的假设与审计周期已定 |
| 定各环节挂法 | human | 定质量表述 | 人拍板：招聘／绩效／培训各自挂上去成为什么动作 |
| 写标准定义 | agent | 定质量表述、定审计节奏 | rule：定义落盘且含质量表述句；agent：通读是否可判 |
| 落判据清单 | agent | 写标准定义、定各环节挂法 | rule：清单落盘；agent：每条判据的取法（rule／agent／human）都填了 |
| 挂到招聘 | human | 落判据清单 | 人拍板：考核的信息量与自主性要求已定 |
| 挂到绩效与培训 | human | 落判据清单 | 人拍板：绩效看什么、培训往哪靠已定 |

先后关系：

```text
定质量表述 ┐
           ├─→ 写标准定义 ┐
定审计节奏 ┘               ├─→ 落判据清单 ─→ 挂到招聘
定各环节挂法 ──────────────┘                └─→ 挂到绩效与培训
```

对着三条逐条看。终态蕴含目标：全部走完，手边有一条可用的标准与它三个环节的挂法，G 成立。依赖保证前置：写标准定义要的正是质量表述与审计节奏这两个前置的后置；落判据清单要的是定义与挂法；挂到招聘要的是判据清单——没有一条边落空。判据可判定：两条 `rule` 判据程序核，其余由人给出是或否。

顺带两处已经攒下但还没利用起来的东西，记在这里免得丢：

- **这个模式的真正壁垒不是技术，也不是产品，是「场的经营能力」**——群里真的在讨论真实问题、选题真的自由、评价真的只看价值、答辩真的较真，四条缺一条，场就塌了。
- **技术类岗位的两条路径要分开**：一个往大规模系统治理走（首席架构师），一个往创新走；他们各自对标 CTO 与 CIO。怎么在岗位设置上区分这两条路径，还没有答案。

## 规格

上面七个任务单元，在本领域的格式里落成一份语言无关的工作流定义：

```yaml
name: 人才质量的标准
description: 为人才质量立一个基本单元，并把它挂到招聘、绩效、培训三个环节上
steps:
- name: 定质量表述
  description: 写清「人才质量」用什么表述，边界在哪
  executor: human
  criteria:
  - executor: human
    description: 表述与边界写死，不留待定项
- name: 定审计节奏
  description: 默认人不可靠，定下持续审计的周期与留痕方式
  executor: human
  criteria:
  - executor: human
    description: 假设与审计周期已拍板
- name: 定各环节挂法
  description: 招聘、绩效、培训各自挂到标准上之后成为什么动作
  executor: human
  criteria:
  - executor: human
    description: 三个环节的动作都已定
- name: 写标准定义
  description: 把表述写成可判的定义，落在 artifacts/人才质量标准.md
  executor: agent
  criteria:
  - executor: rule
    description: 定义落盘
    path: artifacts/人才质量标准.md
  - executor: rule
    description: 写明了产出大于消费、输出高于治理成本
    file: artifacts/人才质量标准.md
    contains: 产出
  - executor: agent
    description: 通读一遍，判得出来吗
- name: 落判据清单
  description: 逐条列出各环节的判据及取法，落在 artifacts/判据清单.md
  executor: agent
  criteria:
  - executor: rule
    description: 判据清单落盘
    path: artifacts/判据清单.md
- name: 挂到招聘
  description: 定招聘考核的信息给到什么程度、要求的自主性到什么程度
  executor: human
  criteria:
  - executor: human
    description: 信息量与自主性要求已定
- name: 挂到绩效与培训
  description: 绩效看什么（回复习惯、产出件数），培训往哪个方向靠（同理心、验收能力）
  executor: human
  criteria:
  - executor: human
    description: 绩效与培训各自看什么已定
```

字段和四样一一对上：`name` 是名字，`executor` 是执行者，`criteria` 里每条判据写着谁判、怎么算完，`steps` 的排列就是选定的那条拓扑序。前置和后置没有自己的字段，写在 `description` 里。

## 实现

**目前还没有可执行形态。** 这是本篇与前面几篇最不一样的地方，如实写在这里。

已经存在的是公开那一侧的档案：招聘的报名与考核方式、岗位编制、提成与激励、绩效方针、入离职管理、高管培养路线，都已经写成了对外的文字。但它们是**描述**，不是**判据**——没有一条能被程序核对，也没有一条写明谁在什么时候审谁。

能先落的是判据里最硬的那一档：回复习惯（是只有「收到」还是明确反馈）、产出的件数与流转，这些写得出 `rule` 判据，落成清单即可交程序核。判不了的那一档——在供应商处境下能否理解对方、沟通是否专业、这个人值不值得长期投入——由 HR 与创始人兑，写清是谁兑、多久兑一次。
