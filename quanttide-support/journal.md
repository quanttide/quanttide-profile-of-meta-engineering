# 客户支持：记录段（journal）

本域在日志仓里记什么、怎么记。客服的记录段是三步：工单 → 工作日志 → 客户确认。工单在这一段收口，办完的判据是「有一份经客户确认的工作日志」，与问题解没解决无关。

## 概念

**工单**——客户提出来的一个问题，一次一条。问题侧：问题常年存在，工单是一次次被提出来的条目；一张工单关掉了，问题可能还在。

**工作日志**——一张工单的处理记录，一份对一份，交客户确认。它是客户确认的载体，也是将来提炼解决方案的唯一原料。按本体系的范畴取名：工作日志记一次事件的现场。

## 落位与写法

- 落 `quanttide-support/<YYYY-MM-DD>.md`，一天一个文件，同日多张工单按时间顺序追加，每段开头标明是哪张工单；
- 一份日志写四样：问了什么（客户原话与上下文）、答了什么（结论与步骤）、依据（查了什么）、结局；
- 结局有四格，都算正常：已确认、超时、客户不回、转出（不该我们答）。不许把后三格记成失败或空着；
- 写完送客户确认，确认结果补记在同一段末尾。

## 规矩

- **只增不改**：写下的日志不回改，错了追加更正段；
- **缺档即建**：当天还没有文件就建，不等提醒；
- **提炼不在这段**：日志里不写「所以我们的方案是……」，方案是加工整理段（`profile.md`）的事。

## 属本段的任务单元

| 任务单元 | 执行者 | 判据 |
|:--|:--|:--|
| 定工单与工作日志的判定 | human | 给定一条记录，当场判得出它是工单还是日志 |
| 定办完的判据 | human | 办完 ⇔ 有经客户确认的日志；超时、不回、转出各记一格 |
| 提问落工单 | agent | 渠道里进来的提问落成工单，字段齐 |
| 回答落工作日志 | human | 每次回答产出一份日志并送客户确认，不是一句对话记录 |
| 核回溯 | agent | 每张办完的工单查得到确认过的日志，缺的退回 |
