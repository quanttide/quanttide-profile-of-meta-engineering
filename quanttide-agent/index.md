# 智能体：元认知档案（quanttide-agent 域）

**目标（创始人原话，2026-11-01）**：「就我自己而言，我的记录总体做的还是比较完善的，所以更多不是挖掘知识经验，而是找到那些AI容易偏离的细节，建立更反脆弱的harness。」

现状：session 以 pi 为主（`~/.pi/agent/sessions`，337 段，按工作目录分 89 个项目目录，JSONL），另有 opencode（81 个文件）、hermes（体量另核）；harness 部件的家已在 `quanttide-profile-of-agent-engineering` 仓（loops、skills、prompts、agents 配置，按业务域组织）。

## 核心循环

**session → 找偏离细节 → 修 harness。**与客服同构的是两段：第一段记录（session → 落档），第二段加工整理（落档 → harness 修正）；不同的是两段的分量——记录已完善，第一段不是瓶颈，整个域的重心压在第二段：**AI 在哪里偏离了预期，就把 harness 修成同类偏离不再发生、或发生时被拉回的结构**。

- **session**——一段智能体会话，原始记录。事件侧，原料。
- **偏离**——session 里 AI 的实际行为与创始人预期之间的落差。第二段的唯一选料入口，比「知识经验」窄得多，也硬得多。
- **harness 修正**——loops、skills、prompts、agents 配置里的一处修订，让某类偏离不再发生或被当场拉回。结果侧：跟场景走，不跟某一段 session 走。
- **反脆弱**——修正不只堵已知的偏离，而是让 harness 的结构在新偏离出现时也容易把它拉回（AGENTS 的判据、循环的检查、缺档即建这类结构都是）。

## 与客服域的对照

| | 客服 | 智能体 |
|:--|:--|:--|
| 第一段产物 | 工作日志（交客户确认） | 落档记录（记录已完善，标偏离） |
| 第一段分量 | 瓶颈（此前根本没记） | 非瓶颈（创始人自述已完善） |
| 第二段选料 | 经客户确认的日志 | 日志里的偏离标记 |
| 第二段产物 | 解决方案（带适用条件） | harness 修正（防再偏/拉回） |
| 第二段判据 | 客户确认 | **待岔路问答** |

## 两段分工与落位

第一段（session → 落档记录，标偏离）落 `journal` 范畴，只增不改，细节见 `journal.md`；第二段（偏离 → harness 修正）落 `profile` 范畴，快照替换、旧版退位，细节见 `profile.md`；要到哪去落 `intention`（未来·自我类），创始人给定、不代配，细节见 `intention.md`；对外口径落 `brochure`，细节见 `brochure.md`。子系统不自建容器。

## 设计范式三段

第一段自己需要才做：量潮自己用智能体干活，先把自己的 harness 修结实。第二段找演化规律：偏离 → 修正 → 结构更强，一次一格。第三段推己及人：售卖口径现在不写，占位。

## 任务单元

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 定 session、偏离、harness 修正的判定 | human | 给定一段记录，判得出偏离在哪、修正落没落 |
| 定修正的判据 | human | 已落死：三级，无终态（假设入档 / 暂时在位 / 证伪退位） |
| 定什么算偏离 | human | 第一条待定判据落死 |
| 定意图 | human | 创始人给定「要到哪去」一句话，岔路问答校验过 |
| 找偏离 | agent | 扫落档记录，把预期与实际的落差标出来 |
| 落 harness 修正 | human | 一处偏离对应一处修订，替换在位旧版 |
| 核不再偏 | agent | 同类 session 复现检查，回写判据 |

## 边界

- 机器上的工作配置（`~/.pi`、`~/.hermes` 等）是采集源，仓是正本；
- 范畴不补领域判断：「偏离」的粒度、修正的判据必须人给，落位再对也枉然。
