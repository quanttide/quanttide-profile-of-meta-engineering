# 智能体：路线图（roadmap）

**本仓收什么**：先动哪只脚。未来·事件类——一步一格，可执行、可验收。

**顺序由洞察撑着。**为什么「先捞后修」而不是「逮着就修」？因为洞察说偏离成批。洞察塌了，顺序跟着重排；没有洞察撑着的步骤是蛮干，不收。

**做完一格，两头对账。**向上用意图验收：这一格走完，「更反脆弱」近了没有；向内验证洞察：捞出来的实况，对得上「成批」吗。对不上就重排，不硬着头皮往下走。

## 现时的候选路线图

1. **捞**——89 个项目目录按偏离描述捞一遍，标出重复出现的偏离模式（依据：洞察「偏离成批出现」；验收：标出的模式有没有第二个实例）；
2. **修**——把最刺的三个偏离修成 harness 规则（依据：上一格捞出的重复模式；验收：三级判据走起来——假设入档、暂时在位、证伪退位）；
3. **堵**——用同类 session 复现检查回看，塌的规则退位换新版（验收：再现偏离触发了几次怀疑与退位）。

## 规矩

1. **一格一验收**：写明这格做完拿什么实况来判，判不了的不收；
2. **不超前于洞察**：洞察还没站住就开下一格，等于蒙着眼走；
3. **超前即回写**：路线图跑完发现意图对不上，是重排路线图，不是把意图改小。

## 任务单元

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 排格子 | human | 每格写明依据哪条洞察、拿什么验收 |
| 核一格完成 | agent | 按验收实况判，不按计划日期判 |
| 重排 | human | 洞察塌或意图对不上时当场重排 |
