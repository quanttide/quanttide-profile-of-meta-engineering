# 智能体：意图（intention）

**本仓收什么**：智能体域要到哪去。未来·自我类——组织在「用智能体干活」这件事上想成为的样子。

**现时的意图表述（创始人原话，2026-11-01）**：「就我自己而言，我的记录总体做的还是比较完善的，所以更多不是挖掘知识经验，而是找到那些AI容易偏离的细节，建立更反脆弱的harness。」这是现时的给定。至于未来态——反脆弱到什么程度算够、边界在哪、什么时候算这个域成了——**待创始人给定，AI 不代配**。

## 规矩

1. **意图只写「要到哪去」**：不写路径、不写指标——路径归 roadmap（未来·事件类），本仓只收方向本身；
2. **创始人给定**：AI 可以从日志与档案里整理候选表述供创始人挑，不许代配、不许外推市场想象或演化路径；
3. **岔路问答校验**：正面陈述看不出分歧，岔路情形看得出——意图每被引用一次做取舍，对不上就改表述、不改人；
4. **快照式**：意图更新是替换，不并存；旧意图由 git 历史取回，仓里只留在位的一份；
5. **当验收标尺，不参与论证**：路线图做完一格，回头用意图验「更反脆弱了吗」；但反过来不成立——意图不由路线图推导（做完什么就顺手把意图改成什么样＝补写，意图失效），也不由洞察支撑（洞察的口粮是证据，意图的口粮是给定）。意图错了，只有创始人判得了。

## 与 insight、roadmap 的对账

路线图两头对账：向上用本仓的意图验收，向内用 insight 仓的洞察验证实况。洞察塌了改洞察、重排路线图；意图对不上只有创始人能判；路线图永远是最后落地的那个。

## 与三段范式的关系

第一段自用的动机就是意图的起点（量潮自己用智能体干活）；第三段推己及人的售卖口径要等意图站住之后再立——意图没定，对外讲什么都是空的。
