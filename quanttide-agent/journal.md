# 智能体：工作日志（journal）

**本域的第一段：session → 落档 → 落档记录。**

**session**——一段智能体会话，原始记录（工作目录、模型、往来消息）。事件侧：一次次发生，一段关掉不代表沉淀消失——没落档的 session 就是散在硬盘上的 JSONL，跟没有一样。

**落档记录**——把一段 session 写成的记录。它是提炼物的唯一原料（提炼在 `data/profile` 仓，不在本仓）。

**办完的判据待定**：客服的对应判据是「有一份经客户确认的工作日志」；session 没有客户，本域的收口判据岔路问答未做，不许先填。

## 落位与写法

1. 落 `data/journal/{业务域}/{YYYY-MM-DD}.md`，一天一个文件，同日同域多段按时间顺序追加；
2. 业务域按 session 的工作目录判：pi 的 session 已按工作目录分目录（89 个项目目录），机械对应即可；工作目录不在任何已知域下的落 `default/`；
3. 一份落档记录写四样：哪个智能体（pi/opencode/hermes）、做了什么（任务一句话）、结果（产出落在哪个仓哪份文件）、结局；
4. 结局有几格**待定**——客服的四格是已确认/超时/不回/转出，本域对应什么岔路问答未做。

## 规矩

- **只增不改**：写下的记录不回改，错了追加更正段；
- **缺档即建**：当天该域还没有文件就建，不等提醒；
- **不留 session 原文副本**：原文在各 harness 的存储里（`~/.pi/agent/sessions` 等），日志只写记录与指针；
- **提炼不在本仓**：记录里不写「所以以后应该……」，提炼是 `data/profile` 仓的事。

## 属本段的任务

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 定 session、落档、提炼物的判定 | human | 给定一段记录，当场判得出它处在哪一段 |
| 定办完的判据 | human | 本域的收口判据落死，四格结局对应什么落死 |
| session 落档 | agent | 按工作目录落对应域，字段齐 |
| 核回溯 | agent | 每份落档记录指得到原 session 的路径 |

领域全景见 `quanttide-meta/data/profile/quanttide-agent/index.md`；冷启动后指领域仓 `domains/quanttide-agent/AGENTS.md`。
