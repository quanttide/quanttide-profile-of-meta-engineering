# 智能体：工作日志（journal）

**本域的第一段：session → 落档记录（标偏离）。**这一段已完善——创始人自述「记录总体做的还是比较完善的」，本仓的职责不是从缺到有，是把已完善的记录对准第二段的需要：**每份落档记录把偏离标出来**，那是 harness 修正的唯一选料入口。

**session**——一段智能体会话，原始记录（工作目录、模型、往来消息）。事件侧，原料。

**偏离**——session 里 AI 的实际行为与创始人预期之间的落差。落档记录的核心字段——没有偏离标记的记录，第二段就无从下手。

## 落位与写法

1. 落 `data/journal/{业务域}/{YYYY-MM-DD}.md`，一天一个文件，同日同域多段按时间顺序追加；
2. 业务域按 session 的工作目录判（pi 已按工作目录分 89 个项目目录，机械对应）；不在任何已知域下的落 `default/`；
3. 一份落档记录写五样：哪个智能体（pi/opencode/hermes）、做了什么（任务一句话）、结果（产出落在哪）、结局、**偏离在哪（预期 vs 实际，一句话）**；没有偏离就写「无」，不省略这个字段。**偏离那句话要写成能比对的形状**：「预期 X，实际 Y」，不写模糊的「AI 偏了」——同任务形态靠偏离描述比对指认，这句话就是检索键；

## 规矩

- **只增不改**：写下的记录不回改，错了追加更正段；
- **缺档即建**：当天该域还没有文件就建；
- **不留 session 原文副本**：原文在各 harness 的存储里，日志只写记录与指针；
- **修 harness 不在本仓**：记录里不写「所以以后应该……」，修正是 `data/profile` 仓的事；
- **偏离的粒度待定**：什么算值得记的偏离（岔路问答未做），暂按「同任务形态下下次还会遇到」的尺度记，宁细勿粗，等判据落定收紧；
- **同任务形态不事前定义**：识别靠事后指认——按工作目录机械筛一遍，再比对偏离描述，对得上才算同一个形态；任务描述对不上、偏离对得上的，以偏离为准。
