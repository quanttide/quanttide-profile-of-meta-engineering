# 智能体：提炼物（profile）

**本域的第二段：落档日志 → 提炼物。**

**提炼物**——从落档日志里提出来、可复用的东西。结果侧：跟场景走，不跟某一段 session 走。本域已有四类现成形态，住 `quanttide-profile-of-agent-engineering` 仓：

- `loops/`——从实践日志提取的循环范式；
- `skills/`——可安装技能（SKILL.md）；
- `prompts/`——提示词；
- `agents/`——各智能体系统配置（以机器上的实际配置为准，cp 即用）。

## 落位

沿用现组织，不另起炉灶：`default/`（未归入领域的通用内容）+ 各业务域目录，域下按 `loops`、`skills`、`prompts`、`agents`、`contexts`、`sessions` 分。

## 规矩

1. **只从落档日志里选料**：哪类 session 值得提炼的选料判据**待定**（岔路问答未做）；凭印象、凭一次性经验写的提炼物不收；
2. **快照式，新版替旧版**：同一场景的循环范式或技能修订后替换，不并存两版；旧版退位，取用只取在位的；
3. **带适用场景**：提炼物写明在什么条件下成立（用哪个 harness、哪个域、什么任务形态）——同一做法在不同场景失效是常态；
4. **指得到来源**：每份提炼物标它从哪些落档日志来（指日期与域），回溯查得到；
5. **以实际配置为准**：涉及 `agents/` 的，从机器上的工作配置采集，不做设计；不重复维护可通过安装获取的内容（继承本仓既有维护规范）。

## 属本段的任务

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 提炼物的选料 | human | 选料判据先落死，再照判据选 |
| 写提炼物 | human | 带适用场景、指得到来源日志 |
| 退位核对 | agent | 被替换的旧版退位，仓里同场景只有一版在位 |

这一段最容易被无限期拖延：第一段跑起来 session 天天有，第二段没有界面也没有期限；拖的时候系统看着一切正常。

领域全景见 `quanttide-meta/data/profile/quanttide-agent/index.md`；冷启动后指领域仓 `domains/quanttide-agent/AGENTS.md`。
