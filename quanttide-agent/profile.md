# 智能体：harness 修正（profile）

**本域的第二段：偏离 → harness 修正。**整个域的重心压在这一段——记录已经完善，剩下的是把偏离变成结构。

**harness 修正**——`loops`、`skills`、`prompts`、`agents` 配置里的一处修订，让某类偏离不再发生、或发生时被当场拉回。结果侧：跟场景走，不跟某一段 session 走。

**反脆弱**——修正的不止是已知偏离。一个好的修正让 harness 结构在新偏离出现时也容易把它拉回：AGENTS 里的判据（「拿不准先问」）、循环里的检查（缺档即建）、退位规矩（同场景只一版在位）都是这类结构。

## 落位

沿用 `quanttide-profile-of-agent-engineering` 仓现组织，不另起炉灶：`default/` + 各业务域，域下 `loops`、`skills`、`prompts`、`agents`、`contexts`、`sessions`。

## 规矩

1. **只从偏离标记选料**：选料入口是日志里的偏离字段，不凭印象——「挖掘知识经验」不是本域的活；
2. **一处偏离，一处修订**：修正要指得到它修的是哪条偏离（指日期与域），也指得到旧版被谁替换；
3. **快照式，新版替旧版**：同一场景的 loops 或 skills 修订后替换，不并存两版，取用只取在位的；
4. **带适用场景**：写明修订在什么条件下成立（哪个 harness、哪个域、什么任务形态）；
5. **以实际配置为准**：`agents/` 的从机器上的工作配置采集，cp 即用，不重复维护可安装的内容——修正直接改工作配置，仓收录其快照；
6. **修正的判据是三级，没有终态**（岔路问答已定，2026-11-01）：修订落地＝假设入档（不是修好了，是写下「这样它不会再偏」的假设）；同类 session 不再偏＝暂时在位（假设未被证伪）；同类偏离再现＝旧规则被拉出来怀疑，证伪就退位换新版，从头再走。「修好了」这个词从本域拿掉——人写的 harness 规则本身不可信，所有规则永远处在「在位待证伪」状态；

## 属本段的任务

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 定修正的判据 | human | 第一条待定判据落死 |
| 修 harness 修正 | human | 一处偏离对应一处修订，假设入档，替换在位旧版 |
| 核不再偏 | agent | 同类 session 复现检查；再现偏离即触发对旧规则的怀疑与退位 |
| 证伪退位 | human | 规则被再现偏离证伪当场退位，换新版 |

这一段没有界面也没有期限，拖的时候系统看着一切正常——记录天天在长，harness 纹丝不动，就是这一段停了。
