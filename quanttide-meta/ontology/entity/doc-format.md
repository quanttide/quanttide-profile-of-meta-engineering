# 文档格式应归类为文档工程（而非叙事工程）

> 决议日期：2026-08-26

## 摘要

本文论证文档格式规范属于文档工程而非叙事工程：其范围是「怎么排」而非「写什么」，只约束格式元素的使用频次与语法规则，属呈现层规范，与叙事工程的内容流程管理分属不同层面。

## 一、来源

- 原文：《量潮科技文档格式章程》
- 仓库：quanttide/quanttide-bylaw-of-business-entity
- 当前路径：`docs/format.md`

文档格式的范围是「怎么排」，不是「写什么」或「如何讲故事」：它约定 Markdown 语法要素（标题层级、列表标记、表格对齐、代码块标注、加粗使用场景等）的使用规则与约束边界，目标是「降低阅读成本，消除因格式混乱导致的信息损耗」，属于典型的呈现层（presentation layer）规范。

## 二、与量潮叙事工程的分界

量潮科技自身对叙事工程有明确定义：其叙事工程档案关注写作内容的流程管理（想法→提纲→草稿→文章四个阶段）与情境化设计（「把用户放在一个情境中，让他们的每个选择都有可感知的结果」）。文档格式不涉及内容创作的叙事结构、信息架构或用户情境，仅约束格式元素的使用频次与语法规则，二者属于不同层面。

## 三、与文档工程学科的吻合

从学科定义看，文档工程（Document Engineering）的核心正是将文档的内容与结构和呈现特性（如格式、排版）分离，建立可复用的文档模型与规范。《量潮科技文档格式章程》所做的事——为 Markdown 文档建立统一的格式标准、定义元素使用边界、甚至将 AI 作为格式执行工具——完全符合文档工程「以文档为中心」的规范化目标。

## 四、结论

若将叙事工程比作「导演决定镜头语言和故事节奏」，文档工程则是「制片方规定字幕字体与片尾格式」。文档格式属于后者：它是保障叙事工程顺畅运行的基础设施，本身并不处理叙事问题。
