# 组织管理

## 摘要

组织管理把量潮创始人控制下的主体和它们之间的关系当成主数据来管：以创始人为根节点，主体与关系各记一张表，业务数据挂在关系下面。

## 一、参与方

| 主体 | 类型 |
|:--|:--|
| 量潮创始人 | 自然人 |
| 量潮创新联盟 | 联盟／组织 |
| 量潮科技 | 公司 |
| 道江网络 | 公司 |
| 量潮实训基地 | 社区组织 |

## 二、关系

关系单独一张表，每条带类型、方向、有效期与依据。

- 量潮创始人 → 实际控制 → 量潮创新联盟
- 量潮创始人 → 实际控制 → 量潮科技
- 量潮创始人 → 实际控制 → 道江网络
- 量潮创新联盟 → 托管 → 量潮实训基地
- 量潮实训基地 → 提供服务／劳务 → 量潮科技
- 量潮实训基地 → 提供服务／劳务 → 道江网络

每条关系挂接协议：控制协议、托管协议、服务合同。业务数据（派工、结算、项目）挂在关系下面。

## 三、常用查询

- 创始人控制哪些主体？沿「实际控制」边遍历。
- 联盟托管了什么？沿「托管」边找。
- 实训基地给谁打工？沿「提供服务」边找。
- 创始人到量潮科技的路径？直接控制；或经联盟 → 基地 → 服务，这是影响链，不是控制链。

## 四、规则

- 实际控制可传递，托管不传递，服务按合同期限。
- 控制关系不能成环。
- 每个公司必须有法定代表人，每份托管必须有协议，每项服务必须有合同。

## 五、落地顺序

1. 录入五个参与方。
2. 录入六条核心关系。
3. 挂接协议和业务数据。
4. 跑一致性检查。

## 六、结论

系统里就是一张以创始人为根的图：控制链看归属，托管链看联盟，服务链看实训基地和两家公司的业务往来。主数据管「谁和谁什么关系」，业务数据管「发生了什么」。
