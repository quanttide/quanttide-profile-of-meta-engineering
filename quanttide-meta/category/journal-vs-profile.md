# 日志与档案：不一致如何逐步收敛

## 摘要

日志与档案是量潮体系中两种并存的信息形态，同一条业务现实同时产生两者的记录时，二者可能不一致。本文用范畴论对这一过程作形式化：日志、档案与主数据各建模为范畴，两套记录到主数据的映射建模为函子；不一致即两函子不自然同构；逐步收敛即构造二者的余极限——自动对齐给出候选余锥，人类确认选定其一，迭代扩展直至余极限稳定。收敛所得的余极限即主数据。

## 一、问题的形式化

量潮体系中：

- 日志是一种形态（范畴），按时间追加事件，记录「发生了什么」；
- 档案是另一种形态（范畴），记录「当前状态是什么」；
- 主数据是实体层精炼后的核心子集。

同一条业务现实可能同时产生日志与档案。以一次营销活动为例：

- 日志记：「10月1日投放了A渠道，10月3日调整了预算，10月5日暂停了B渠道。」
- 档案记：「当前活动状态：进行中，预算30万，主渠道A。」

两者可能不一致：日志暗示活动经历过暂停又恢复，档案却只显示「进行中」，丢失了过程信息。量潮体系允许这种不一致存在，再逐步收敛。用范畴论描述该过程，核心是三个概念：函子、自然变换、余极限。

## 二、基本设定：每种形态是一个范畴

把每种信息形态定义为一个范畴：

- 日志范畴 L：对象是事件，态射是事件之间的时序关系（「A发生在B之前」）；
- 档案范畴 A：对象是状态快照，态射是状态之间的转换关系（「状态X变为状态Y」）；
- 主数据范畴 M：对象是精炼后的实体实例，态射是实体间的语义关系。

从日志和档案到主数据，各有一个函子：

- F: L → M：把日志中的事件序列映射为主数据中的事实断言；
- G: A → M：把档案中的状态快照映射为主数据中的事实断言。

函子保持结构：日志里「A先于B」，F 把它们映射为 M 中两条有先后关系的事实；档案里「状态X变为Y」，G 映射为 M 中两条有转换关系的事实。

## 三、不一致即两个函子不重合

F 和 G 对同一现实给出不同的主数据断言，这就是不一致。范畴论上，这表示 F 和 G 不是自然同构的：不存在可逆的自然变换 η: F ⇒ G，使得对 L 中每个对象，F 的像与 G 的像一一对应。

具体表现为三类：

- 信息丢失：日志中的「暂停又恢复」事件，在档案中可能只留下「进行中」状态，G 丢掉了 F 保留的过程信息；
- 粒度差异：日志按事件粒度记录，档案按状态粒度记录，同一段时间日志有十条事件，档案只有一条状态；
- 视角冲突：日志说「活动暂停过」，档案说「活动进行中」，两者都对，但描述的是不同侧面。

在范畴论里，这不叫「错误」，而叫两个函子之间的自然变换不构成同构。它允许存在，只是标记为「未收敛」。

## 四、逐步收敛即构造余极限

收敛的目标，是找到一个共同的主数据视图，让 F 和 G 都能一致地映射进去。范畴论中，这个共同视图就是余极限（colimit）。

### 4.1 余锥：候选的共同视图

余锥是一个对象 C，加上两个态射：

- α: F(L) → C；
- β: G(A) → C；

使得对 L 和 A 中所有对象，α∘F 和 β∘G 给出相同的结果。换言之，C 是 F 和 G 的共同目标，两者映射到 C 后不再冲突。

每个余锥是一个候选的一致视图。例如：

- C₁：以日志为主，档案补充状态字段——日志的「暂停又恢复」保留，档案的「进行中」作为当前状态附加；
- C₂：以档案为主，日志作为历史附件——状态以档案为准，日志作为变更依据；
- C₃：新建统一视图，同时保留事件序列与状态快照，用时间轴对齐。

### 4.2 余极限：最佳的一致视图

余极限是所有余锥中最通用、信息损失最小的那个，满足泛性质：任何其他余锥都唯一地通过它分解。

在工程上，余极限对应的是：找到一种主数据结构，能同时容纳日志的事件序列和档案的状态快照，且不丢失任何一方能提供的信息。例如：

```text
主数据实体：营销活动
  ├── 当前状态（来自档案）
  ├── 状态变更历史（来自档案的态射序列）
  ├── 事件时间线（来自日志）
  └── 事件与状态的对应关系（F 和 G 的映射）
```

日志和档案都映射到这个结构，且映射结果一致。

### 4.3 逐步收敛：构造余极限的迭代过程

余极限不是一步到位的，而是逐步构造的，范畴论中对应过滤余极限（filtered colimit）：

1. 每一步选取一个有限子图（部分日志加部分档案）；
2. 构造这一步的余锥，得到一个局部一致视图；
3. 下一步扩展子图，把新数据纳入，重新构造余锥；
4. 新数据与已有视图冲突则调整余锥，不冲突则扩展余锥；
5. 所有数据纳入且余锥稳定，即得到余极限。

该过程正是「允许不一致，再逐步达成一致」的数学表达。

## 五、收敛的驱动机制：自然变换与人类确认

余极限的构造需要驱动力，量潮体系中有两个。

### 5.1 自然变换：自动对齐

当 F 和 G 的像之间存在结构保持的对应关系时，存在自然变换 η: F ⇒ G，它标记出：

- 日志中的哪些事件对应档案中的哪些状态转换；
- 哪些事件在档案中没有对应（信息丢失）；
- 哪些状态转换在日志中没有记录（记录缺失）。

自然变换是自动对齐的候选，标记出一致和不一致的部分。

### 5.2 人类确认：选择余锥

自然变换给出候选对齐，但选择哪个余锥作为最终一致视图需要人类确认，因为：

- 不同余锥代表不同的信息取舍策略；
- 「以日志为主」还是「以档案为主」是业务决策，不是数学推导；
- 人类确认后，余锥被固定下来，成为新的主数据规范。

在范畴论上，人类确认相当于在余锥的格（lattice）中选一个点：所有余锥构成一个偏序集，人类选择其中最优的（或最符合业务需要的）那个。

## 六、完整的形式化描述

定义：

- L：日志范畴；
- A：档案范畴；
- M：主数据范畴；
- F: L → M，G: A → M：两个函子；
- η: F ⇒ G：自然变换（候选对齐）；
- Colim(F, G)：F 和 G 的余极限（最佳一致视图）；
- Cone(F, G)：所有余锥的集合（候选一致视图）。

过程：

1. 初始状态：F 和 G 不一致，η 不构成同构，Colim 未定义；
2. 自动对齐：计算 η，标记一致和不一致的部分；
3. 人类确认：在 Cone(F, G) 中选择一个余锥 C；
4. 余极限构造：C 满足泛性质则 Colim(F, G) = C，否则扩展 C 重新构造；
5. 迭代：新数据加入后重复步骤 2 至 4；
6. 收敛：Colim 稳定，F 和 G 通过 η 一致映射到 Colim，不一致消除。

## 七、工程落地

范畴论概念与工程实现的对应关系：

| 范畴论概念 | 工程实现 |
|:--|:--|
| 日志范畴 L | 日志形态的实体表和关系表 |
| 档案范畴 A | 档案形态的实体表和关系表 |
| 主数据范畴 M | 主数据实体表和关系表 |
| 函子 F、G | ETL／映射规则，把日志、档案转为主数据断言 |
| 自然变换 η | 自动对齐算法，标记日志与档案的对应关系 |
| 余锥 Cone | 候选的一致视图方案，存 `convergence_candidate` 表 |
| 余极限 Colim | 最终一致视图，写入主数据并标记 `converged` |
| 人类确认 | 审批界面，选择余锥方案 |
| 过滤余极限 | 增量收敛流程，每批新数据触发一次 |

表结构示例：

```sql
-- 候选一致视图
CREATE TABLE convergence_candidate (
    id TEXT PRIMARY KEY,
    log_entity_id TEXT,
    archive_entity_id TEXT,
    alignment JSON,          -- 自然变换的对应关系
    strategy TEXT,           -- 以日志为主 / 以档案为主 / 融合
    status TEXT DEFAULT 'pending',
    approved_by TEXT
);

-- 收敛后的主数据
CREATE TABLE converged_master (
    id TEXT PRIMARY KEY,
    entity_id TEXT,
    log_refs JSON,           -- 关联的日志
    archive_refs JSON,       -- 关联的档案
    alignment JSON,          -- 最终对齐关系
    converged_at TIMESTAMP
);
```

## 八、结论

日志和档案是两个范畴，F 和 G 是两个函子，不一致是 F 和 G 不自然同构；逐步收敛的过程，就是构造 F 和 G 的余极限：自动对齐给出候选余锥，人类确认选择一个余锥，迭代扩展直到余极限稳定，收敛后的余极限就是主数据。

该过程允许不一致存在，不强制统一；用自然变换标记差异，用余锥提供候选，由人类确认选择，用迭代逼近余极限。这是量潮体系「允许多形态共存，再逐步达成一致」的范畴论表达。
