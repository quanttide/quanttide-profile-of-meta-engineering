# 交互设计：命名表（profile）

**本域的第二段：命名事件 → 命名表条目。**整个域的重心在这里——命名是分水岭，表就是那道岭的落地。

**命名表**——每范式一条，快照式维护。这是本域的核心资产：把创始人「熟悉但叫不出名」的东西接上通行词汇，让范式可以在对话里被直接叫出来、被 AI 和组件库听懂。

## 条目写法

1. **英文原名＋中文对照**（如 master-detail / 列表-详情）——名字从社区通行词汇对齐取用，不发明；
2. **定义**：一句话，说清这个范式组织的是什么；
3. **实践的适用条件**：量潮在什么情况下选它——不收光秃秃的市场定义；
4. **实例**：哪次设计用了（指回 `data/journal` 的命名事件，应用＋日期）；
5. **出处**：社区通行名的链接（设计模式语言、组件库文档），AI 检索靠它。

## 规矩

1. **只从命名事件选料**：表里的每条指得到 journal 侧的事件；市场清单上抄来的不收——只从真实实践收录；
2. **快照替换，不并存**：一条的定义或适用条件修订后替换旧版；
3. **没对上的挂候选区**：journal 里记了「没对上」的描述，挂候选区等创始人定——要么社区确实没有（自造名归创始人），要么继续找；
4. **名字归用户**：AI 对名给候选，采纳才落表。

## 属本段的任务

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 对名 | agent | 英文原名＋中文对照＋出处，候选不落表 |
| 落表 | human | 创始人确认采纳，字段齐 |
| 修订条目 | human | 有新命名事件作依据才改 |

这一段没有界面也没有期限——命名事件天天可能遇到，表不动就是这一段停了。
