# 咨询：关系档案（profile）

**本域的第二段：接触落档 → 关系档案。**整个域的重心在这里——重点是管理咨询关系，档案就是关系的载体。

**关系档案**——每家企业一份，快照式只放当前最新版。记录这段关系现在是什么状态：两端是谁（量潮 ↔ 企业）、企业是谁、谁在内部服务（专家是内部资源，不挂档案正名）、关系的死活、上次接触。

**关系的死活判据已落死（2026-11-01）**：看客户有事还想不想得起我们——哪怕八个月没开会话，企业遇到事第一反应来找我们，关系就在；再不来了才算断。会话节奏是关系健康的**结果**，不是判据。

## 落位

每家企业一份，落 `{企业}/` 目录下与接触记录同住（`data/profile` 仓内按企业分目录，结构与日志侧对齐）。

## 规矩

1. **快照替换，不并存**：每次接触后更新，旧版直接被新版覆盖；历史由日志与 git 承担，档案只留当前版；
2. **字段待定**：一份关系档案写哪几样，对着真实企业核（创始人给定第三条待定判据）；核死之前先维护最小集——企业是谁、关系死活、上次接触日期、内部谁在服务；
3. **只从接触记录更新**：档案的每处更新指得到它来自哪天的接触（指回 `data/journal` 侧）；凭印象写的不收；
4. **内部服务者不挂正名**：专家是内部资源，档案里记「内部谁在服务」，但关系的正主是量潮 ↔ 企业。

## 属本段的任务

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 定关系档案字段 | human | 对着真实企业核死 |
| 维护关系档案 | human | 每次接触后更新，替换不并存 |
| 核对账 | agent | 档案每处更新指得到接触记录 |

这一段没有界面也没有期限，拖的时候系统看着一切正常——接触天天在记，档案纹丝不动，就是这一段停了。

领域全景见 `quanttide-meta/data/profile/quanttide-consult/index.md`；冷启动后指领域仓 `domains/quanttide-consult/AGENTS.md`。
