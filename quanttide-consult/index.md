# 咨询：元认知档案（quanttide-consult 域）

**意图（创始人给定，2026-11-01）**：「我们的重点是管理咨询关系。」对标心理咨询——核心资产是关系本身，会话只是关系里的事件；之前的原型做错了形态，做成了项目制。产品形态：一个入口，lite 提供一个轻的，studio 提供更完整的。

**真身（现有材料，散）**：
- 2026-08-20 战略日志：想明白咨询业务——参考心理咨询的商业模式，挖经管学者的专业能力，资源对接，联盟做渠道，市场价一两千一小时；
- 2026-10-13：咨询面对大量新企业，市场时差客观存在；
- 2026-10-22：咨询与云一起，是企业服务变现的路；
- 2026-09-30 产品日志（负信号，已由创始人重新定性）：量潮咨询 APP 与业务有距离、AI 生成似是而非——原因是形态做错成项目制，不是方向错；
- `qtconsult` 应用仓在（Dart），客户业务数据走本地目录不进仓。

## 核心循环

**接触 → 关系档案。**一段咨询关系里发生的每次接触（会话、消息、见面）落档；每家企业一份关系档案，快照式维护。关系是本域的一等对象——不是工单，不是项目，不是会话记录。

## 已落死的判据（岔路问答，2026-11-01）

1. **关系的两端是量潮 ↔ 企业**：专家是量潮内部资源，企业认的是量潮的牌子，关系档案挂量潮名下，不挂专家名下；
2. **关系的死活看客户有事还想不想得起我们**：哪怕八个月没开会话，企业遇到事第一反应来找我们，关系就在；再不来了才算断。会话节奏是关系健康的**结果**，不是判据——拿节奏判会把「关系好但会话少」误判成断档。

## 待定判据（岔路问答未做，不得先填）

1. **「想得起我们」的观测落点**：判据 2 的代价是不好观测，什么接触能证明「想得起」，落点待定；
2. **lite 与 studio 的分界**：两档入口各收什么量级的诉求，待定；
3. **关系档案的字段**：一份关系档案写哪几样，对着真实企业核，待定。

## 两段分工与落位

第一段（接触 → 落档记录）落 `journal` 范畴，只增不改，细节见 `journal.md`；第二段（落档 → 关系档案）落 `profile` 范畴，快照替换，细节见 `profile.md`；要到哪去落 `intention`，对世界的判断落 `insight`，先动哪只脚落 `roadmap`，对外口径落 `brochure`。子系统不自建容器。

## 与前两域的对照

| | 客服 | 智能体 | 咨询 |
|:--|:--|:--|:--|
| 一等对象 | 工单 | 偏离 | 咨询关系 |
| 第一段产物 | 工作日志（交客户确认） | 落档记录（标偏离） | 接触落档 |
| 第二段产物 | 解决方案 | harness 修正 | 关系档案（每企业一份） |
| 死活判据 | 客户确认的工作日志 | 无终态，证伪退位 | 客户有事想不想得起我们 |
| 判据落点 | 明确可查 | 明确可查 | **待定（第一待定判据）** |

## 任务单元

| 任务 | 执行者 | 判据 |
|:--|:--|:--|
| 定接触、关系档案的判定 | human | 给定一条记录，判得出它是接触还是档案字段 |
| 定「想得起」的落点 | human | 第一条待定判据落死 |
| 定 lite/studio 分界 | human | 第二条待定判据落死 |

| 接触落档 | agent | 按企业分目录，字段齐 |
| 维护关系档案 | human | 每次接触后更新快照，替换不并存 |
