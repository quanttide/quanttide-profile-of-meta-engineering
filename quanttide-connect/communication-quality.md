# 本地 AI 输出的沟通质量治理

## 需求

人机之间相互听不懂，本身就是一个沟通问题。本地 AI 信息量太大，输出混乱——信息熵高、缺乏层次、没有优先级标注；这与人跟团队成员沟通时「想得太复杂、大家听不懂」是同构的毛病：脑子里东西太多、思维链路太长，直接倒给别人的时候，接收方的解码成本就爆了。目的是人类和 AI 相互理解：不要求表达风格、叙事风格跟人类靠近，先保证 1 对 1 的日常沟通能够讲清楚；最终靠人类确认，AI 可以用置信度等方式外化辅助理解。

这句话拆开是四件事：沟通质量由什么判定（标签从哪来）、评分由谁做（机器评分信不信）、规则怎么立（凭证据还是凭直观）、治理动作落在哪里（生成时、输出前还是事后）。必须定的决策全在判定与规则一侧：失败事件算哪些、特征入池凭什么条件、机器评分的信度怎么核；用哪个 embedding 模型、压缩比阈值取多少，是参数不是决策。

拆的时候盯三件事：标签从哪来，特征凭什么入池，评分信到什么程度。

## 意图

拆之前先问：这件事里有什么东西真实存在。

摊开看，真实存在的是七样。**对话**——人与 AI 的一段往来记录，治理的原材料。**失败事件**——对话里可观察的沟通失败：追问、要求复述、「没听懂」、执行了错误动作、人大幅改写 AI 输出。**标签**——一段对话被判定含有的失败事件。**特征**——从输出文本算出的量；具体指标不预列，候选须按 A2 先交付预测力证据。**规则**——进入输出前检查的判定条款，逐条带预测力证据与适用边界。**评分**——机器对一段输出沟通有效性的判断。**干预**——改变输出形态的动作：结论先行、每段一个观点、优先级标注。

据此立下的核心断言有三条：

```text
A1  沟通质量由解码成本的行为学事件判定，不由表达风格判定
A2  规则的入池条件是与失败事件标签的预测力，不是指标的直观合理性
A3  机器评分定位为筛选器，裁判权在人类确认
```

这三条确实改动拆法。原设计是「先让 AI 打分，再手工立规则，数据挖掘倒推」——评分在前、标签后置；按 A1–A3，失败事件标签是起点，特征检验居中，规则库在末尾，任务序列整个反过来。机理判断「混乱是结构缺失，不是信息熵过高」（Shannon 熵定义在信源上，不定义在单段文本上；高熵而结构清晰的文本好懂，低熵的车轱辘话照样难懂）是待验证的假设，不据此预列指标，也不为「信息熵怎么测」单开任务。每个候选指标带一句「测什么、不测什么」，缺声明视为未交付。

排除两条：表达风格靠拢不做——A1 已把判定锚在事件上；模拟情绪外化不进这轮拆解——对解码成本是净增项，置信度外化保留。

任务单元：

| 任务单元 | 执行者 | 前置 | 判据 |
|:--|:--|:--|:--|
| 定失败事件清单 | human | 无 | 人拍板：追问、复述、没听懂、执行错误、改写量各写成能从对话记录判定的条件 |
| 挖标签 | agent | 定失败事件清单 | rule：失败事件标注可从对话记录复算；抽样复核不一致的对话退回重标 |
| 提特征验预测力 | agent | 挖标签 | rule：每个特征交付一份报告——与失败事件标签的预测力、该特征测什么、不测什么；缺声明视为未交付 |
| 立规则库 | human | 提特征验预测力 | 人拍板：入池规则逐条带预测力证据与适用边界，无证据不入池 |
| 上输出前检查 | agent | 立规则库 | rule：每条输出发出前过检查，未过检查的输出不出现在已发送记录 |
| 抽样人核评分 | human | 上输出前检查 | 人拍板：可疑样本的人工判定与机器判定一致率达标，未达标回滚该批规则 |

评分侧的防偏置约束随任务走：成对比较代替绝对打分、rubric 拆到每条规则一项、多 judge 交叉、定期抽样本与人工判定对齐——针对的是机器评分已知的长度偏好、位置偏好、自我偏好。

偏序：

```text
定失败事件清单 ──→ 挖标签 ──→ 提特征验预测力 ──→ 立规则库 ──→ 上输出前检查 ──→ 抽样人核评分
```

链外独立一条：**先干预**。结论先行、每段一个观点、优先级标注直接做成输出前检查，不依赖标签；测量体系的价值在验证改善与发现非显然模式，先干预后测量。

对着三条分解条件核。终态蕴含目标：六项走完，失败事件可判、规则有证据、输出有检查、评分有人核，「1 对 1 讲清楚」落成可查的动作。依赖保证前置：每项前置都来自上游任务的判据。判据可判定：两条人拍板由人给是或否，三条 rule 程序核得过。最容易漏的是链外那条：只顾走链，先干预一步没动，日常沟通的改善就全押在还没建成的测量体系上。

## 规格

工作流定义成一句话：「失败事件 → 标签 → 特征检验 → 规则库 → 输出前检查 → 人核评分」一条链，链外挂一条先干预。

程序管得住的：特征计算（每个指标附「测什么、不测什么」声明）、标签复算（按失败事件清单扫对话记录）、检查闸门（不过检查不发送）、人机一致率统计。只能人核的：失败事件清单是否仍代表「听懂了」的真实判断；规则适用边界是否仍然成立——规则库自身可被预测力复验推翻；抽样判定本身；机器评分的三种偏置有没有渗进规则。

指标基线随规格走：任何候选指标先固定长度窗口、同语言基线再比较；短文本上压缩类指标不稳，不单段使用。
