# 市场：加工整理段（profile）

本域在档案仓里做什么。市场一侧的加工整理段只有一件事：从日志记录提炼当前的营销认知快照。原料只有日志仓 `quanttide-market/` 的记录；日志里提出但还没有可描述形态的问题，原样收进快照标「待收敛」。

## 概念

**快照**——一副骨架（范畴、层级、关系与约束）加它在各情境上的部署。替换侧：只放当前最新一份，更新时替换，不并存，旧版退位。

**待收敛**——日志里提出、尚未落死的原问题。开放侧：原样收进快照，不替创始人下结论。

## 落位与写法

- 收在本目录 `quanttide-market/`，文件名围绕业务场景本身，不用方法词——「无声营销」是方法词，不进文件名；
- 一条快照写三样：骨架（观察、信任品、无声营销、命名四层及其约束）、部署（哪些情境、骨架怎么落）、待收敛（没落死的原问题）；
- 日志有新记录、判断改变了才替换快照，不因措辞好坏重写。

## 规矩

- **只从日志出发提炼**：快照的每条断言指得到日志日期，凭印象写的认知不收；
- **不补领域判断，不给建议**：策略该怎么定是人的事，档案只记当前认知；
- **快照替换不并存**：修订后替换原文件，不留并列版本。

## 属本段的任务单元

| 任务单元 | 执行者 | 判据 |
|:--|:--|:--|
| 定提炼的入口 | human | 待岔路问答——什么状态的日志算「够提炼一次」，判据尚未落死 |
| 日志入快照 | agent | 新日志落位后，快照的骨架或部署有对应更新，或明确记为待收敛 |
| 核出处 | agent | 快照每条断言指得到日志日期，指不到的退回 |

这一段最容易被拖掉：记录段天天在长，快照没有界面也没有期限；拖的时候日志看着一切正常。
