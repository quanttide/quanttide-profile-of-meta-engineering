# 按验收标准设置课程

## 需求

课程设置通常从内容出发：先定教什么、排几周、布置哪些任务，最后才想怎么考。考法跟着内容走，内容一改考法跟着改；改过几轮之后，没人说得清这门课到底要学员到什么程度才算过。

换个角度：先立验收标准——结课时学员交出什么、按什么判过——再倒推课内该练什么任务、评什么维度。标准在前，任务是为覆盖标准而设的。

这个角度不是凭空选的。《改进招聘考核流程》那篇已把招聘考核定义为《生产实习》这门课，标准随课程走；课程怎么设置、标准怎么立，于是直接决定招聘判得准不准。

这句话派不出去。它由好几件事攒成：验收标准谁来定、每条写到什么程度才算可判、任务怎么对齐标准、分级与通过规则定在哪、谁核对齐。真正必须定的决策全在标准一侧——每条标准是什么、过线定在哪；内容怎么措辞只是文案。这些不定，「从验收标准出发」就落不成实事：课照排，考照旧临场定。

拆的时候盯三件事：派给谁，怎么算完，得等谁先做完。

## 意图

拆之前先问：这件事里到底有什么东西存在。

摊开看，真实存在的是五样。验收标准——结课时判过不过的那条断言，必须明写、算得出真假；它是这件事的单位。课程——标准、任务与评分规则挂靠的容器，招聘已定义为《生产实习》这门课。任务——学员在课内做的事，一个任务是覆盖某几条标准的手段。评价——评委按标准对交付物的一次打分。结论——这门课对一个学员的最终判定，一人一个。任务排在第几周说的是安排，安排本身不占一样东西。

据此立下的判断是：课程设置的单位是「一条验收标准」，任务是标准的覆盖手段，不是独立实体。课设得对不对，不看内容排得多满，看每条验收标准是否都有任务练到、有评价测到、结论可由 pass 重算。离开这条判断先排内容再补考法，定出来的永远是内容大纲，不是课程。

承接《改进招聘考核流程》的 Criterion：`dims`、`grade` 把表现记下来，`pass` 负责判过。从验收标准出发设置课程，就是先立 `pass` 要用的断言，再倒推 `dims` 与任务——次序反过来，标准才立得住。

归位之后，把拆法写成可判定的式子。先看课程长什么样：

```text
课程 ::= name  : Str
         crit  : Criterion                # 验收标准挂在课程上，不随内容改
         tasks : List[Task]
         cover : crit 的每条标准 → 至少一个任务
```

一个任务单元记四样东西：

```text
任务单元 ::= 名字
             执行者 : {智能体, 人}
             前置   : 状态上的条件
             后置   : 状态上的条件
             判据   : 可判定的完成条件
```

判据的取法沿用前几篇：`rule` 是程序机械核对，`agent` 是智能体判，`human` 是人拍板；步骤本身的执行者只有 `agent` 与 `human` 两种。

一条需求写成目标，落在最终想要的产物上：

```text
目标 G ≡ 对 crit 中每条验收标准 a：
         存在任务 t 覆盖 a，存在评价按 grade 记录 a，
         且 结论 = pass(评价)
```

分解是拿出一组任务单元 T = {t₁, …, tₙ}，再给出先后关系 ≺，要满足三条：

```text
(1) 终态蕴含目标   post(t₁) ∧ … ∧ post(tₙ) ⇒ G
(2) 依赖保证前置   tᵢ ≺ tⱼ ⇒ post(tᵢ) ⇒ pre(tⱼ)
(3) 每个 tᵢ 的判据可判定
```

≺ 是个偏序，允许两件事谁也不等谁，不允许有环。

拿「设置一门课」走一遍。六个任务单元：

| 任务单元 | 执行者 | 前置 | 判据 |
|:--|:--|:--|:--|
| 定验收标准 | human | 无 | 人拍板：每条写成可判定断言，过不过当场算得出 |
| 定评价维度与分级 | human | 定验收标准 | 人拍板：每条标准都有对应维度与等级描述 |
| 定通过规则 | human | 定评价维度与分级 | 人拍板：pass 规则写死，给定评价重算得同一结论 |
| 倒排任务 | agent | 定验收标准 | rule：任务清单落盘；agent：每条标准至少被一个任务覆盖 |
| 核覆盖与孤儿 | agent | 倒排任务、定评价维度与分级 | agent：无未覆盖的标准、无落空的任务、无空维度，缺项退回 |
| 排课实施 | human | 核覆盖与孤儿、定通过规则 | 人拍板：课表落盘，周次对着任务、任务对着标准 |

先后关系画出来是这样：

```text
定验收标准 ──┬─→ 定评价维度与分级 ──┬─→ 定通过规则 ──────┐
             │                      │                    │
             └─→ 倒排任务 ──────────┴─→ 核覆盖与孤儿 ────┴─→ 排课实施
```

对着三条逐条看。终态蕴含目标：六个走完，每条验收标准立下了、有维度记着、有任务盖着，pass 写死且课表对着它排，G 成立。依赖保证前置：倒排任务等的是标准立下，正是它前置任务的后置；核覆盖等的两件（维度与任务）分别来自它的两个前置任务；排课实施等的两件同样对得上。判据可判定：一条 `rule` 判据程序核得了，两条 `agent` 判据由智能体逐条过，四条人拍板判据由人给是或否。

三样里最容易漏的是第二条。人排课习惯按周次排，排出来看着顺，但「核覆盖与孤儿」若只等「倒排任务」不等「定评价维度与分级」，维度空着的标准照样没人记，到结课才发现评不了。偏序把这个漏洞摆到明面上：漏一条依赖边，图上就少一条箭头。
