# quanttide-profile-of-meta-engineering

量潮元认知快照记录

本仓记录元工程领域**当前最新**的元认知档案：此刻对「一件事如何被认出来、如何拆成可执行单元」的最新认知。

## 定位

快照式——只放当前最新的一份。认知更新时，文件被替换而不是并存；旧版留在各自的来源仓与日志里，本仓不做版本堆叠。

档案按主体分目录，一个主体一个目录：

| 目录 | 记什么 |
|:--|:--|
| `quanttide-think/` | 认知骨架本身：量潮认知模型（QCM） |
| `quanttide-founder/` | 这副骨架在创始人三个集上的部署 |
| `quanttide-agent/` | 智能体一侧的档案 |
| `quanttide-relation/` | 主体之间关系的档案 |
| `quanttide-human/` | 招聘与考核一侧的档案 |
| `quanttide-media/` | 新媒体运营一侧的档案 |
| `quanttide-market/` | 市场一侧的档案：观察、信任品获客与无声营销 |
| `quanttide-course/` | 课程设置一侧的档案 |
| `quanttide-delib/` | 议事与决议一侧的档案 |
| `quanttide-connect/` | 沟通一侧的档案：人机之间如何把一件事讲清楚 |
| `quanttide-support/` | 客户支持一侧的档案：工单与解决方案 |
| `quanttide-meta/` | 元工程体系自身的档案 |

## 概述

本仓只收元认知快照——一副骨架（范畴、层级、关系与约束）加它在各主体上的部署，按主体分目录，快照替换不并存。

**四阶段分解流程不在本仓。**需求、意图、规格、实现的流程已由 quanttide-code 吸收为正式体系，教程在教程仓；在元工程档案仓收具体问题的四阶段，会让本仓陷入具体问题。具体问题的四阶段分解落各自领域的仓。
